---
title: "aristowrap 0.1.1: the returned archive is treated as hostile, and the tests cover everything"
date: 2026-10-14
tags: [lean4, tool]
---

[aristowrap](https://github.com/carlok/aristowrap) — the Docker-first wrapper that submits a Lean 4 project to Harmonic's Aristotle and typechecks the archive it returns — shipped [0.1.1](https://github.com/carlok/aristowrap/releases/tag/v0.1.1), a maintenance round that starts from the archive being untrusted input: `verify` applies the tar `data` filter on every interpreter that has it (3.11.4+, not only 3.12+) and refuses to extract at all on one that does not, reporting refused members as "unsafe archive rejected"; `submit` no longer uploads symlinked `.lean` files, which could point outside the project; and a prompt starting with `-` is no longer parsed as an `aristotle` option, because a `--` separator now precedes it ([9b0cd7c](https://github.com/carlok/aristowrap/commit/9b0cd7c)). A missing `aristotle` or `lake` gives a one-line error and exit 127 instead of a traceback, Ctrl-C stops the child and exits 130, `--destination` with `--no-wait` is rejected rather than silently ignored, and a warning goes to stderr when `ARISTOTLE_API_KEY` is unset, where `aristotle` itself still exits 0.

Test coverage went from 66% to 100% by putting fake `aristotle` and `lake` binaries on `PATH` that record their argv and cwd, so `submit` and `verify` run end to end without network — path-traversal and escaping-symlink archives, newest-tarball selection, shallowest-lakefile resolution, staging pruning — and the floor now lives in `pyproject.toml` at `fail_under = 90` ([df1225b](https://github.com/carlok/aristowrap/commit/df1225b)). The image is pinned end to end: elan comes from a checksummed release asset rather than a script that always fetched the latest, uv from the pinned `ghcr.io/astral-sh/uv` image instead of `curl | sh`, `aristotlelib` pinned at 2.1.0 because the wrapper depends on its CLI flags, and the in-image tests run through `uv sync --frozen` against `uv.lock` ([1f903e2](https://github.com/carlok/aristowrap/commit/1f903e2)).

CI lost the duplicate `docker-image.yml` workflow that pushed the same tags twice, pins its actions to commit SHAs, runs ruff check and format before the tests, and pushes `:latest` from `main` as well as from a `v*` tag, with Dependabot watching Actions, uv and Docker ([6592f83](https://github.com/carlok/aristowrap/commit/6592f83)); the same round added CONTRIBUTING, SECURITY, CHANGELOG and the issue and PR templates, and fixed README claims that had drifted — a `--wait` flag that does not exist, a prompt file not in the repo, host defaults, and the `verify` trust model, which builds untrusted Lean and is meant to run read-only and without the API key ([96af62b](https://github.com/carlok/aristowrap/commit/96af62b), [d22eed3](https://github.com/carlok/aristowrap/commit/d22eed3)). Dependabot then moved the base image to `python:3.14-slim-bookworm` ([#4](https://github.com/carlok/aristowrap/pull/4)), and the `chore/python-3.14` branch adds 3.14 to the test matrix and the classifiers to match ([4d26ff8](https://github.com/carlok/aristowrap/commit/4d26ff8)).
