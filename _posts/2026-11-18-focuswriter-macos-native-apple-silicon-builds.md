---
title: "focuswriter-macos: native universal builds of FocusWriter, because the last official Mac build is Intel-only"
date: 2026-11-18
tags: [project, tool]
---

[focuswriter-macos](https://github.com/carlok/focuswriter-macos) went public on 18 November, GPL-3.0, and holds packaging scripts only: it builds the **unmodified** upstream release tag of [FocusWriter](https://gottcode.org/focuswriter/), Graeme Gott's distraction-free word processor, and publishes universal (Apple Silicon + Intel) DMGs on its own Releases page — [v1.9.1-mac2](https://github.com/carlok/focuswriter-macos/releases/tag/v1.9.1-mac2) ships the disk image, its checksums and the exact corresponding source tarball. The reason is the Mac build itself: the last official one is Intel-only, so it runs through Rosetta on an Apple Silicon machine while macOS warns that Intel apps will not be supported, so the build uses official Qt 6.12.0 from `aqtinstall` and targets macOS 14.4 or later.

Two `macdeployqt` behaviours in Qt 6.12.0 had to be worked around in [`scripts/deploy.sh`](https://github.com/carlok/focuswriter-macos/blob/main/scripts/deploy.sh): it copies `imageformats/libqsvg` only when the executable already links QtSvg, and FocusWriter reads SVG backgrounds through `QImageReader` without linking it, so a plain deploy ships no SVG reader at all; and with Homebrew Qt it copies `iconengines` and `platforminputcontexts` from kegs whose frameworks sit outside its search path, which yields rpath errors and a bundle that only works on the build Mac. Placing `libqsvg.dylib` in the bundle first and passing it with `-executable=` makes the tool copy QtSvg and rewrite the plugin's install names like any other binary, and [`scripts/audit.sh`](https://github.com/carlok/focuswriter-macos/blob/main/scripts/audit.sh) fails the build if any Mach-O file in the bundle loads something from outside it or lacks an arm64 or x86_64 slice.

The builds are ad-hoc signed and **not notarized** — that needs a paid Apple Developer account — so each release carries SHA-256 checksums and a GitHub build provenance attestation tying the DMG to the workflow run and commit that produced it, with the one-time Gatekeeper step documented. The repo was deliberately kept downstream rather than offered upstream: FocusWriter's `CONTRIBUTING.md` bans contributions generated by LLMs "in all parts of the project", and pull requests and issues are disabled on the GitHub repository, so a separate packaging repository needs nothing from the author — and a [weekly workflow](https://github.com/carlok/focuswriter-macos/blob/main/.github/workflows/watch-upstream.yml) opens an issue here when upstream tags a version newer than the pinned `UPSTREAM_TAG`.
