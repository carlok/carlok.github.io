---
title: "cdclkit and dratify: a soundness campaign whose oracle shares no code with either"
date: 2026-11-09
tags: [tool, security]
---

The soundness campaign that produced [dratify 0.1.11](/blog/2026/11/09/dratify-0-1-11-deletion-of-a-reason-clause/) and [cdclkit 0.2.0](/blog/2026/11/09/cdclkit-0-2-0-campaign-fixes-native-denied/) landed on 9 November as its own branch in both repositories, and the branch is the part the fixes do not show: `campaign/` holds an oracle that shares no code with either implementation, checked by a second agent against the definitions in Wetzler–Heule–Hunt 2014 and Rebola-Pardo–Biere 2018, one seeded generator per corner, the findings and the results ([dratify#15](https://github.com/carlok/dratify/pull/15), [a164034](https://github.com/carlok/dratify/commit/a164034); [cdclkit#15](https://github.com/carlok/cdclkit/pull/15), [6b87a99](https://github.com/carlok/cdclkit/commit/6b87a99)).

Dratify's oracle decides satisfiability by brute force on at most 16 variables; cdclkit adds a small DPLL for encodings past that. Nine corners in dratify — RAT, deletion, root level, literals, `ok` against `reached_empty`, parsing, API shapes, engines, and drat-trim with `rate` 0.3.0 as outside opinions — ran 262,655 instances and 3,386,486 steps, and five corners in cdclkit — encodings, preprocessing, MUS, modelling, engines — ran 23,037 instances and 4,651,241 checks; duplicates are collapsed across corners, and the deleted reason clause turned up independently from several of them at once. Three Critical defects in dratify, each confirmed by a second agent with the oracle and by hand, became three advisories ([GHSA-xccm-c64j-hf7g](https://github.com/carlok/dratify/security/advisories/GHSA-xccm-c64j-hf7g), [GHSA-2j4v-jw9r-f4gw](https://github.com/carlok/dratify/security/advisories/GHSA-2j4v-jw9r-f4gw), [GHSA-v562-gjx2-cg8p](https://github.com/carlok/dratify/security/advisories/GHSA-v562-gjx2-cg8p)), and cdclkit's seven became one ([GHSA-82pg-jv96-v48m](https://github.com/carlok/cdclkit/security/advisories/GHSA-82pg-jv96-v48m)).

What the campaign is worth is mostly in the run after the fixes: an independent sweep, written to share no code with the generators or the tests, took 40,000 random instances at seed 90210 and found no false refutation and no difference between the engines on any field, where the same sweep on the old code found 167 in 60,000. The reports stay quiet on purpose — a README sentence was to be proposed only if nothing Critical came out of the campaign, so neither repository gets one — and `campaign/REPORT.md` in each carries the corner tables, the per-defect verification file and the mismatches left open as Notes ([cdclkit report](https://github.com/carlok/cdclkit/blob/main/campaign/REPORT.md), [dratify report](https://github.com/carlok/dratify/blob/main/campaign/REPORT.md)). One correction sits in the report rather than in a follow-up: cdclkit's list first had drat-trim in its own corners, and drat-trim ran in dratify's ([e753eb8](https://github.com/carlok/cdclkit/commit/e753eb8)).
